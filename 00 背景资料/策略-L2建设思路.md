## 一句话总览

**L1 是散落的政策文件,L3 是给老板的月报。L2 把前者织成网、把信号浓缩成可直接抄进月报的页面**。

L2 = 4 步派生:`standardize → relate → crystallize → reverse`,落成 8 类资产。

---

## 为什么需要 L2

L1 是 263 篇政策 + 150 篇评论的扁平堆。直接喂月报会面临:

- **同一实体多个写法**:发改委 / 国家发展改革委 / NDRC / 发改 — 检索/统计看不准
- **政策互相引用却没有显式链接**:政策开头"根据 X 文件",X 是哪一篇要靠人记
- **同一主题政策散落在 vault 里**:虚拟电厂相关政策有 30+ 篇,需要一个聚合页
- **看一篇政策不知道它后续被多少政策引用过**:反向追溯断裂

L2 就是为了解决这四类问题,把 L1 织成可消费的知识图谱。

## 4 步建设原则

### 1. standardize(标准化)

把所有 L1 文档的 frontmatter 拉成统一 schema:`id` / `title` / `date` / `region.{level,code,name}` / `provenance.{source,url,fetched_at}` / `issuer` + `issuer_canonical`(canonical 列表) / `tags` / `重要性`(1-5)。

工具:`standardize_issuer.py` / `policy_id_assign.py` 等。

成功指标:**`daily_lint` L1/L2/L4 全 pass**(必填字段齐 / id 唯一 / region 不"未知")。

### 2. relate(建关系网)

8 类 typed relations 抽取,严格按 schema_v3 §6 定义:

| 关系 | 抽取方式 | 当前 |
|---|---|:-:|
| supersedes(显式废止) | regex(标题"废止/取消"等) | 2 |
| iterates(版本升级) | regex(版本号 / 修订标记) | 12 |
| extends(范围扩展) | regex + LLM | 8 |
| clarifies(实施细化) | regex(标题"实施细则/操作办法") | 46 |
| references(文号引用) | regex(《xxx》模式)+ title_match 二轮 | 172 |
| aligns_with(同向对齐) | LLM | 4 |
| conflicts_with(口径冲突) | LLM | **0**(详见洞察 2) |
| cites_basis(制定依据) | references 子集 + LLM 判"作为依据"语义 | 54 |

关键工程:`extract_relations_regex.py` / `extract_evolution_v2.py` / `extract_cites_basis.py`。

### 3. crystallize(浓缩结晶)

把"散落多处的同主题政策"压成 1 个聚合页。

**主题结晶 4 件套**(每个 theme 必备):
- `overview.md` — 主题定义 + 政策清单 + 时间分布
- `timeline.md` — 关键政策时间线 + 演进路径
- `regional-coverage.md` — 区域覆盖分布
- `opinions-summary.md` — 该主题的舆论矩阵 + 严格模式覆盖率声明

**区域索引**:每个 ≥3 篇政策的省/市/区生成 1 个区域页。

工具:`build_themes.py`(按 theme entity 拉所有挂该 tag 的政策) / `build_regions.py`。

### 4. reverse(反链)

每篇被引用的政策生成 `_index_by_policy/<P_id>.md`,列出 8 类入向边。

工具:`build_reverse_links.py`(待写,当前 71 反链页是手工+部分自动)。

⚠️ **schema 改良 todo**:**每政策都该有空壳反链页**(哪怕入向度=0,也写"该政策暂无下游引用,可能是末端实施文件"),`daily_lint` 跑"反链覆盖率"暴露孤岛。

## 三个核心洞察(决定下一轮做什么)

### 洞察 1 · 中文政策不爱明说关系,规则抽取上限 ~30%

**现象**:supersedes 漏抓 96% / iterates 漏抓 67% / aligns_with 仅 4 边。

**根因**:中国政策文本的"协调机制"既消除显式冲突,也消除显式关系标记:

| 想找的关系 | 西方文献写法 | 中国政策写法 |
|---|---|---|
| 废止 | "This supersedes Act X" | 不写,只在国务院总台账登记 |
| 迭代 | "Version 2.0 of X" | "完善 / 修订 / 优化" 等模糊词 |
| 引用 | "[1] Smith (2018)" | "根据 X 精神" / "结合实际" |
| 同向 | "Aligned with Y policy" | 不显式,要读论调 |

**结论**:规则抽取(标题/正则)只能抓显式表达 → 漏掉大量隐式关系。**上升路径必须用 LLM 读正文细节**。

### 洞察 2 · conflicts_with = 0 不是 bug,是国情合理结果

161 候选 LLM 全否,曾被列为"数据稀疏"。**实际是抽取面错向**:

中国政策协调机制(党管 / 国务院常务会 / 两办联合发文 / 党组讨论)在政策出台前就消除了显式冲突。所以扫 263 篇政策两两找冲突 → 必然 0。

真正的 conflicts 形态在**评论层**:
- 跨部委口径差(能源局 vs 环境部)→ 学者点出
- 中央 vs 地方执行差 → 行业观察
- 不同时间窗口 → 已被 iterates 覆盖
- 细节口径差(数字/时间表) → **唯一**能在政策正文找到
- 暗冲突(细则反向修正) → 已被 clarifies 包装

**正确架构**:conflicts_with 应从 `policy↔policy` 改为 `commentary→[policy_a, policy_b]`(评论指出政策冲突)。**body_3000 扩版本是错的方向**。

⚡ **方法论教训**:**抽取脚本设计前先问"这个关系类型在中文政策语境里以什么形态显化?"**,不要照搬西方学术文献的关系类型。中国政策更"含蓄",显式标记少,需要从评论层挖。

### 洞察 3 · opinion 是 L2 的"血肉",依赖 L1 评论桶 A 类

opinion 覆盖率 20.5% 是 L2 最大短板。L1 评论桶 A 类原创只占 9.9%,且**100% 来自 PDF / 官网,0 个来自公众号** — L1 之前完全没碰过公众号矩阵。

**所以 L2 改良的前置不是改 L2 抽取脚本,而是先补 L1 A 类内容** — 这正是 [[策略-公众号补源-wewe-rss]] 在做的事。补源后 opinion 重抽,coverage 应能到 50-70%。

## 与 L1 / L3 的关系

```
L1(0_raw/)              L2(1_extracted/ + 2_crystallized/)         L3(月报)
──────────────────────  ──────────────────────────────────────  ──────────
策略-八步采集法            ─→ standardize ─→ entities                  ─→ 实体口径
策略-公众号补源(wewe-rss) ─→ relate     ─→ relations + reverse     ─→ 演进对比
                          ─→ crystallize─→ themes + regions       ─→ 主题章节
                          ─→ (LLM)     ─→ opinions(舆论温度计)    ─→ 市场反应
                                       ─→ _global_index            ─→ 数据规模
```

**重要边界**:
- L1 不动,L2 只读不改 L1
- L2 全部派生自 L1 + 抽取规则,**可重跑可重建**
- L3 月报抽 L2 但不改 L2(L3 只读)

⚡ **核心原则**:L2 任何派生资产都应**幂等**(同输入二跑结果一致)。LLM 调用要 `temperature=0`。
