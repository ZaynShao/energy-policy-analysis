# 当 AI 开始批量写 HTML，WorkBuddy 想解决「生成之后」的问题

「人人都应该有一个 AI 工作台」，最近这段时间，网络上掀起了一阵搭建个人工作台的热潮。
先是一位百万级大网红用 WorkBuddy 几句话搭出了一个专属工作台，视频发出后，抖音、小红书的评论区随即变成了「大型交作业现场」——有人搭自媒体选题看板，有人做健身打卡记录，有人给一年级孩子做暑期学习计划，有人整了短视频带货管理系统……
但热闹之下，一个共性问题也很快浮出水面：工作台搭起来容易，用起来却卡壳了。
不少用户在晒完新鲜感之后，很快发现了同一个坑——数据只存在本地。在办公室电脑上录的一条待办，回家打开手机，空的；手机上记的一笔账，回到电脑上看，没有。原因很简单：AI 生成的 HTML 工作台，数据默认存储在浏览器的 localStorage 里，这是「这台设备 + 这个浏览器」的专属空间，换个设备、清个缓存，数据就没了。
小红书上的「踩坑帖」和「避坑指南」随之扎堆出现——有人研究怎么手动备份数据库文件，有人折腾三端迁移教程，有人写脚本定时同步本地数据。为了让一个「几分钟搭好的工作台」能真正用起来，用户反而要做大量技术活。
这是 AI 生成 HTML 的另一个尴尬：它能快速生成一个「看起来能用」的系统，却没有提供一个「能持续用」的底座。生成的门槛降下来了，但维护、同步、协作的门槛还横在那里。
WorkBuddy 这次升级的资料库，尝试把这一断点接起来：一方面，将原有「人机双写」延展至 HTML 与智能 Markdown，让用户可以直接修改页面、选区让 AI 定点改、邀请同事协作，并将成品一键发布为链接；另一方面上线「轻应用」，以 HTML 做交互界面、智能 CSV 承载数据，尝试让网页从一次性展示内容，变成可持续更新的个人工作台或团队看板。
这次升级的真正价值，在于验证一些更具体的问题：当网页进入真实工作流后，AI 生成的 HTML 能不能像文档一样被修改、审阅、协作、分享，并在数据变化时继续可用？
极客公园通过实测，尝试验证 WorkBuddy 资料库是否真的降低了 HTML 的「最后一公里」门槛，以及「轻应用」对个人和小团队工作台意味着什么。
01
网页生成之后，
普通人究竟能不能把它改好、协作好？
AI 生成网页的门槛已经降得很低，但「生成完成」往往不等于「可以交付」。
一个更常见的场景是：AI 做出了一份完整的 HTML 汇报页，临近交付时，负责人要改标题，客户要换一张主视觉，同事还要补充一组数据。面对 PPT，团队至少知道该怎么分工修改；面对 AI 生成的 HTML，很多人的第一反应却是：这段代码谁能动？
这正是本次实测想了解的问题。WorkBuddy 将「人机双写」延伸到 HTML 后，能否让不会写代码的人，像修改文档一样修改网页；又能否让 AI、人与协作者围绕同一份页面继续工作，而不是在生成之后重新回到文件传递和代码沟通？
先从一份真实的方案汇报页开始测试。我准备了一份提示词，让 workbuddy 生成包含项目背景、传播主题、节奏规划、预算分配和预期效果的 HTML 页面；页面完成后，不做整体推倒重来，而是提出几个工作中最常见的修改需求。
请制作一份「AI 戒指新品发布整合传播方案」HTML 演示页，用于向客户提案。
页面需要包含：项目背景、核心传播主题、三阶段传播节奏、渠道规划、预算分配、预期效果六部分。整体使用黑白银色高级简约风，适合大屏展示；数据部分使用图表呈现，并预留图片位置。项目背景为：一款可听可语音输出可记录的 AI 语音戒指。

对非技术用户而言，真正的门槛从来不是让 AI 写出第一版代码，而是在此之后，能否低成本地反复修改、推翻和重来，workbuddy 的这次更新实现了这一点。它的 HTML 编辑走的是「所见即所得」路线——看到什么就改什么，不需要碰代码。但如果你懂一些前端，也可以切到代码层面做深度定制，两种用户都能找到自己的入口。
我随后将页面发给了我的同事，给他开了编辑权限，可以看到，他的更新动作实时也同步显示在页面，改 html 就像一起协作文档一样流畅自然。

这也是 HTML 与传统 PPT、在线文档相比最值得观察的地方。它们并非谁替代谁：PPT 仍适合成熟的演示工作流，在线文档也依旧是高频协作工具；但当内容需要持续更新、嵌入交互元素，并以链接而非附件交付时，HTML 有机会成为另一种更轻的表达形式。
如果用户能直接改，AI 能够被精确调度，协作者也能在同一页面上接力，HTML 才不只是 AI 的一次性输出，而开始成为团队可维护、可复用的表达资产。当然，涉及复杂交互、深度定制或敏感信息分享时，专业开发工具与更严格的权限机制依然不可替代。
除了 HTML，这次「人机双写」还延伸到了 Markdown。传统 Word 的修订模式只能记录人的修改痕迹，WorkBuddy 这次的智能 Markdown 文档给 AI 的修改也加了一道审阅环节。AI 提出的修改建议会以批注/建议修订的形式呈现，用户可以逐条审阅、接受或修改，接受后才最终写入正文。
对于不信任 AI「一键生成」结果的人来说，这个设计解决了一个顾虑：AI 可以帮忙写，但最终拍板的是人。
02
页面会「存数据」之后，
AI 做的工作台能不能真的跑起来？
协作编辑解决的是「做出来以后怎么改」，轻应用要解决的则是另一个更实际的问题：当网页不只用于展示，而要记录数据、持续更新时，它还能不能继续用？
很多人已经用 AI 做过个人工作台、旅行规划页、内容看板，甚至小店经营系统。但其中不少页面的数据只存在本地：换一台设备，记录没了……WorkBuddy 这次的更新也把这个问题解决了。

回头看，轻应用解决的核心问题可以用一个字概括：活。访问是活的——发布成链接，别人点开就能看；修改是活的——人能直接改，AI 能定点改，同事能一起改；数据是活的——可以在 HTML 存储数据，多端实时同步。网页也成为了一个持续运转的系统。
当然，这套能力有其适用边界。对于涉及复杂业务逻辑、高并发数据写入或严格权限管控的场景，专业业务系统依然不可替代。但对于那些还不值得专门买系统、也等不起开发排期的轻量需求，AI 提供了一条介于「手搓表格」和「定制开发」之间的路径。
03
AI 时代的 Office，
为什么开始需要一套新的文件组合？
前面的实测已经分别验证了两件事：AI 生成的 HTML 能否被普通人继续编辑和协作，以及它能否在接入数据后成为持续更新的工作台。所以，为什么 WorkBuddy 要把 HTML、Markdown、CSV 放进同一个资料库？
AI 可以生成用于协作沉淀的 Markdown、用于展示和发布的 HTML，也会处理 CSV 这类结构化数据。问题在于，这些内容往往仍散落在聊天记录、本地文件和不同工具里——生成之后，用户还要自己承担整理、修改、协作和复用的成本。
在 WorkBuddy 此次升级里：Markdown 承接内容写作和审阅，HTML 承接演示、交互和发布，CSV 承接数据记录与更新；资料库则试图将三者沉淀在同一个可被人和 AI 共同调用的空间中。前文测试的「方案页协作」和「个人工作台」，正好对应这条链路的两端。
WorkBuddy 减少了内容在「写完—搬运—重新排版—再次维护」之间的反复消耗，这并不意味着 HTML 会取代 PPT，Markdown 会取代 Word，轻应用也未必会替代专业业务系统。更值得关注的变化是，AI 时代的办公内容正从彼此孤立的文件，变成一套能够持续流转的组合：Markdown 用来完成写作、讨论和审阅，HTML 将内容转化为可交互、可分享的呈现，CSV 则为页面提供可更新的数据基础。
三类原本分散的内容重新放进同一个工作空间：内容写完后不必反复搬运和排版，数据更新后不必重做页面，下一次任务也可以继续调用此前沉淀的文档和资料。如何让 AI 生成的内容真正进入后续的协作、展示和管理流程，正是「AI 时代 Office」的核心要义。
作为覆盖 Win、Mac、鸿蒙、安卓全平台、深度集成腾讯文档等生态的效率智能体，WorkBuddy 把 HTML、Markdown、CSV 这三种 AI 原生格式放进同一个资料库，本质上是在为「AI 时代 Office」搭一套新的底座——让 AI 原生的格式变得人人可用。
