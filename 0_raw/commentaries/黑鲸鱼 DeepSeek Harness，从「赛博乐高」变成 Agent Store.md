# 黑鲸鱼 DeepSeek Harness，从「赛博乐高」变成 Agent Store

8 月 14 日上午，DeepSeek Harness 上线 GitHub 还不到十二小时，项目 GitHub Star 就突破了 5 万。跻身 GitHub 史上最速达成记录之列。
极客公园曾在首发实测总结它的「一切皆插件」的概念是，「Agent 界的 Android」，但这个评价的另一面，是当时社区围绕 DeepSeek Harness（下文简称 DSH）的巨大争议：「对非开发者不是很友好」与「毛边随处可见」是不少第一时间体验之后的评论；还有一些第三方测显示同样跑 V4 Flash，DSH 比别家 harness 多烧三倍 token。
但五天之后，DSH 在社交媒体平台上已经经历了一轮完整的「口碑反转」：不仅 GitHub 达到了 14.9 万星，1.5 万个 fork。「赛博乐高」的概念也已经被社区所接受，已经累积起了超过 5100 个插件与超过 3500 位作者。
DeepSeek Harness 开源第五天的 GitHub 仓库页，星标 14.9 万、fork 1.5 万｜图片来源：GitHub
乍一看，这是一次寻常的口碑回暖 —— 东西还行，用的人多了，风向自己会转。
但我觉得其实真正的原因，还得是 DSH 这个看起来非常工程师文化的「一切皆插件」概念，以及由此延伸出的更具想象力的使用方式：
Harness 可以更加开箱即用，直接交付满足千人千面用户需求的 Agent
01
口碑反转靠社区
DSH 的口碑反转，其实从一开始就有迹可循：发布后的第二天夜里，一个名为 anywhere-labs 的团队把官方版本打包成了开箱即用的桌面应用。不用装 Node，不用敲命令行，服务自动拉起，插件能力和 Web 界面全保留。这个项目在两天内就收获了超过 4700 Star。
社区做的 DSH 桌面版，简介写着「万物皆『插件』，桌面本身也是『插件』」｜图片来源：GitHub
由于原本 webUI 以及代码部署的方式，对非代码用户来讲确实不够友好，因此不少人也立即投入了「为 DSH 造壳」的竞赛中：有开发者用 Tauri 重做一版安装包仅有 100MB 的版本；又有人用 Python 加 pywebview 压到更加离谱的 18MB。
8 月 16 日，有人发现 DeepSeek 把自家工程团队每天在用的十来个 Skill 也一并放了出来：有按仓库自己的标准做 code review 的，有专门抓过度设计和死代码的，还有清理文档里残留思维链的。
仓库 .agents/skills 目录下的十来个内部工程 Skill，从 code review 到文档规范｜图片来源：GitHub
有开发者评价到：资深工程师脑子里那些说不出口的经验，第一次变成了可以执行、可以复用、可以审计的「Skill」。
这个剧本其实我们也并不陌生：Stable Diffusion 刚出来那阵，所有人都在折腾 Python 环境和 CUDA，后来 AUTOMATIC1111 和 ComfyUI 来了，整合包来了，真正把它送到普通人手里的，还得是枝繁叶茂的第三方开发生态；Skill 能快速出圈也是同理。
毕竟大家虽然都喜欢当极客，但真的没人喜欢吃苦，大家都是来偷懒的。
这也是为什么这两天，你能在各种社交平台上看到无数网友根据自己喜好，发布的各种「DSH 十大插件榜」；这些榜单的前三名，往往是类似改前端 UI 的 dsh-web-ui，以及给纯文本模型装上眼睛的 modlens，还有把侧边栏改成完整的 IDE ；当然还有从 Claude Code 和 Cursor 搬家过来的迁移工具。
原本 DSH 相比其他 Harness 产品的明显劣势：界面丑、不能读图、没有 IDE 形态、没有 TUI、搬家麻烦。五天之内，已经全部被社区给填上了坑。如今已经迅速长成了有着超过 5100 个插件、超过 3500 位作者的庞大生态。
在旧的 Harness 开发生态中，「界面丑」「不能读图」是只有官方才有资格修复的缺陷。你提 issue，然后等。在这里，它变成了一道社区四十八小时就交卷的题。
产品没做完，头一回成了一个可以外包给社区的问题。甚至某种程度上成为了如今 DSH 的一项优势。
所有关于 DeepSeek Harness 的嘲讽和反转，其实本质上是同一个架构的因果两端。正因为它把自己拆得够碎，才既显得「毛坯房」，又能被社区在五天里快速补完。
02
从赛博乐高到「 Agent  广场」
虽然「一切皆插件」是 DSH 的核心概念，但在此之前并不是一个大家广泛熟悉的认知。
要紧的是架构文档里的另一句话：没有可打补丁的特权内核。想扩展它，不是改源码，是在旁边挂一个插件；插件卸载时，在运行时里注册过的东西全部回滚 —— 就像拼乐高一样，你很难说其中哪块积木真的就是那个 「主心骨」。
官方架构文档原文：没有可打补丁的特权内核，扩展方式是在旁边挂一个插件｜图片来源：GitHub
对照着看，非开源的 Claude Code 给用户开放了四个接口：MCP、插件、Skill、Hook，外加七档权限。口子做得很成熟，但开在哪，始终是 Claude 官方说了算。
DeepSeek Harness 则完全没有这个中心。模型适配器、工具注册表、文件系统、沙箱、终端、任务调度，全在同一层，全能换——连 agent 的主循环本身都是插件。它只咬死一样东西：日志。
模型看见过什么，就必须记下什么，任何进入模型请求的内容，都要能从日志里重建出来。
这套逻辑推到尽头，是一个极具试验性的「赛博乐高」概念：Agent 可以检查自己正在运行的插件树， 甚至现场给自己挂一个临时插件，用完再拆掉。
虽然目前这个权限默认没有打开，还要从源码构建才碰得到；挂进去的代码权限和 Bash 一样大，插件也只活在当前进程里。但 DeepSeek 已经将方向展示给了整个行业 —— 连「给自己加插件」这件事本身，也可以一个插件。
当社区逐渐接受这个概念后，就迅速在此基础上衍生出了另一个新概念「Preset 预设」：简单来讲就是一种基于 DeepSeek Harness 现有这套「赛博乐高」架构，直接分发 Agent 的模式。
基于预设概念延伸出的 DeepSeek Harness Agent 市场｜图片来源 DSH Desktop
区别于我们已经熟悉的 Skill，Preset 可以同时在 DSH 中整合不同插件，组装起同时包括 Skill、网页浏览/搜索、文件生成、上下文策略等几乎所有 Agent 能力，并一键将其交付出去。
换言之，预设交付给用户的，其实是一个完整的 Agent 能力。社区中甚至已经出现了专用于分发 Preset 的网站，用于一键部署对应的科研 Agent、视频制作 Agent 等预设。
直接交付 Agent 对 Harness 产品来讲仍然是颠覆性改变｜图片来源：DSHDesktop
另一层让 DSH 插件生态快速蓬勃发展的因素，是开源本身，你可以从源码本身看清整个系统架构中，事实归谁所有、权限卡在哪道闸、什么要落成持久记录、模型能看到哪部分、坏了怎么恢复。整套架构会成为未来所有想要借鉴 DSH 经验的 Harness 团队的基石。
这套交付模式显然比起「赛博乐高」要更加适合所有人，不少行业大牛立即意识到其中的潜力所在；曾写出 Flask 框架的 Armin Ronacher 如今在带队做 Pi，发布次日下午，他就在 X 上公开表态：DeepSeek Harness 并不完美，「但这确实是我头一回看到这个领域里的新东西，被触动到想重新审视我们自己的一些选择。开源的这一面，我太喜欢了」。
竞品 Pi 的掌舵者、Flask 之父 Armin Ronacher 的公开表态｜图片来源：X @mitsuhiko
五天时间里，社区把智谱 GLM、月之暗面 Kimi、Qwen、Claude、Gemini 全接了进来。有个视觉识别插件支持十五家以上的供应商，从阿里、智谱一路排到腾讯混元和火山豆包。
智谱、Kimi、Qwen、混元、豆包，全在 DeepSeek 的架子上｜图片来源：GitHub
虽然 V4 Pro 至今不支持多模态，但社区也没等 DeepSeek 补 —— 大家直接用插件把图像任务路由给智谱和阿里的模型，文本继续留在 DeepSeek 手里。
甚至已经有人，把 DeepSeek Harness 塞进 Claude Code 和 Codex 里，当一个真正的子 agent 用 —— 自带工具集和沙箱工作区，不是转发一次 API 调用；也有插件反着来，让 DeepSeek Harness 把活派给 Codex 和 Claude，还能续上之前的线程。
Harness 这一层，正在从各家的护城河逐渐「管道化」。谁的模型在里面跑、谁给谁打下手，如今都变成了配置文件里的一行。
公平地讲，DeepSeek Harness 发布当天晚上的头十二个小时，社区里各种关于它的吐槽声音，其实都都没错。
它就是毛糙，就是没管非程序员的死活。但或许「没打算做完」一开始就是 DeepSeek 想要在自家 Harness 尝试中，想要交付出的核心产品 —— 把最该攥在手里的那一层拆开、摊平、公开，让所有人踩上去，甚至包括对手。
这个构想与所有爆款项目指标都无关，它很大程度上代表了 DeepSeek 对于 Harness 这类产品的一个更宏大的构想：
Harness 本身不应该是产品，Agent 才是。
