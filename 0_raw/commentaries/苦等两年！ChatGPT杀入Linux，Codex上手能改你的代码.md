# 苦等两年！ChatGPT杀入Linux，Codex上手能改你的代码

新智元报道
刚刚，Linux用户苦等了两年的客户端，终于落地了。
OpenAI官宣：ChatGPT桌面应用的Linux版本，开放预览。
ChatGPT、Work和Codex，从此装进同一个App。
Linux是开发者密度最高的系统之一，却一直被OpenAI官方桌面端漏掉。
过去两年，Windows和macOS用户敲个快捷键就能唤出ChatGPT，Linux用户只能把它挂在浏览器里。
而这回补上的，也不只是一个入口。
三件套一起进来，尤其是Codex，能碰到你的项目、代码库和终端，这是浏览器永远够不着的地方。
Codex视图：左上角切换ChatGPT，侧边栏的Pull requests到Projects一个没少。
首批支持的发行版有：Ubuntu 24.04和26.04 LTS、Debian 13、Fedora 43和44。
Linux有几百个发行版，OpenAI先挑了三家的五个版本。覆盖面不大，但挑的都是下游发行版的底座。
架构给了x64和ARM64两条线，安装包直接备齐.deb和.rpm，双击就可安装。
据TechCrunch报道，这版预览已经面向全球开放，新版ChatGPT桌面应用集齐了macOS、Windows、Linux三大桌面操作系统。
OpenAI官方说，Linux一直是桌面端呼声最高的平台之一。
官宣当天，OpenAI Developers账号翻出一条两个多月前的旧回复：5月22日，一个叫Joel Handwell的网友在评论区喊：给Linux出个Codex App吧。
对一个常被调侃「只服务浏览器用户」的AI公司来说，这一步来得不算早。
这次，不只是ChatGPT终于有Linux版了那么简单。
三件套中，ChatGPT负责对话，Work负责复杂的多步骤任务，Codex负责真正动手干活。
这里的Work，指的是面向复杂、多步骤任务的智能体体验，能不能用取决于你的套餐和工作区设置。
而Codex，虽然和ChatGPT装进了同一个应用，却依然保留着自己的独立视图。
OpenAI帮助中心文档中这样写道：Codex的工作流没有改变，历史记录也和ChatGPT的历史记录分开。
你在ChatGPT里聊需求，在Work里推进多步骤任务，在Codex里让它下手改代码，中间不用再来回切应用。
一句话概括：一个壳，两套记忆，三种干活方式。
同一个会话里，Codex列出了创建并验证Google Doc的五项内容：源码、程序说明、编译运行命令、预期输出、验证细节。
过去两年，OpenAI的产品线一直在做加法：网页版、桌面版、Codex独立App、Atlas浏览器。
现在，它开始做减法了。
把时间线拉长看，这次Linux补位，其实是这轮产品收口的一步棋。
7月9日，OpenAI一口气办了三件事：发布ChatGPT Work，把独立的Codex应用并进新的ChatGPT桌面应用，顺手砍掉Atlas浏览器。
Chat、Work、Codex，三个界面被重新打包进同一个入口，当天就在Mac和Windows上全球开放，所有套餐都能用，包括免费版。
老版桌面应用则改名叫ChatGPT Classic，退到一旁。
8月9日，Atlas正式停止工作。
三天后，Linux版上线。
收口对于OpenAI和用户来说，好处都很明显。
用户到手的，是省事。不用再纠结「这活儿该开哪个App」，一个应用，三个都在。
OpenAI收获的，是用户黏性。所有入口收拢成一个，你的上下文、文件、项目、习惯，全落在同一个客户端里。
装进你电脑的那个App越重，换掉它的成本就越高。
为什么说这一版最该兴奋的是开发者？
以往Codex在桌面端能碰到的东西，浏览器版永远碰不到：本地项目、代码库、文件系统、终端。
这四样，恰好就是一个工程师一天耗时最久的地方。
把一个能读你代码库，并能敲你终端的智能体，直接放进电脑，和在网页里复制粘贴代码，完全是两种体验。
前者是AI同事，后者只能算是一个搜索框。
这也是今年AI编程工具的一个分水岭。
写代码这件事，早已不缺补全和建议了，缺的是一个能自己跑通「读代码、改文件、跑命令、看报错、再改一遍」的整个循环。
而这套循环，只有在本地才跑得起来。
Codex在Linux桌面上写完hello_chatgpt.cpp并完成编译，右侧代码区与左侧对话区并排，底部模型为5.6 Sol Medium。
OpenAI给这个应用的定位也很明确：项目管理、文件处理、浏览器工作流，加上本地的Codex开发工作。
同一个会话里，Codex把编译成功的消息发进了用户的Slack私聊。
有意思的是，社区里已经有人发现，它在Windows的WSL Ubuntu 24.04环境里也能跑起来。
至于功能对齐程度，OpenAI的Codex负责人Tibo给出的说法是，基本上与其他平台持平。
「Linux版」不等于所有Linux都能装。
目前明确的只有Ubuntu、Debian、Fedora的指定版本，Arch、openSUSE、RHEL、Linux Mint还不在官方名单里。
ChatGPT桌面版跑在Debian 13上的实际画面。
官方首批支持的这些发行版，本身就是大量下游桌面发行版的底座，理论上兼容面会更宽一些。
但「理论上能跑」和「官方承诺支持」，在生产环境里是两回事。
还有两条也得留意。
一是它到现在仍是预览版，功能和套餐是否与macOS、Windows完全一致，官方并没有明确说明。
二是虽然官方也给出了ARM架构的安装包，不代表你手里那台ARM设备就一定能跑，桌面环境、系统依赖和硬件要求，官方还没有完整公布。
回头看，OpenAI给Linux用户留的那个登记页面，其实7月中旬就出现了。
那时候页面上没有下载链接，只有一个「通知我」表单，还顺手问了一句：你用哪个发行版。
Ubuntu、Debian、Arch、Fedora、RHEL，选项列出一排。
现在Ubuntu、Debian、Fedora进了首批，Arch和RHEL还得再等等。
Codex和Work能接触本地文件、项目和终端，这是它最大的卖点，但权限边界怎么划、沙箱怎么做、企业环境里怎么管，比「有没有客户端」重要得多。
一个能敲你终端的智能体，想进公司的电脑，得先过运维这一关。
在Linux这件事上，OpenAI并不算领跑。
大约一个月前，Anthropic的Claude桌面版就上了Linux，支持Ubuntu 22.04及以上、Debian 12及以上，覆盖的版本线甚至更老、更宽。
这几乎是最近一年OpenAI、Anthropic双雄竞赛的保留剧本：
一家先把口子撕开，另一家在一个月内跟上，谁也不敢把开发者这块阵地让出去。
因为开发者不只是用户，他们还是布道者：一个工程师把工具装进公司电脑，往往就等于带进来一个团队。
而代码这块阵地，也恰恰是两家最近咬得最狠的地方。
今年2月，OpenAI给Codex发了独立桌面应用；6月初，官方宣布Codex周活用户突破500万，而年初这个数字还只有60万左右，五个月翻了8倍。
用户构成也在变：大约20%的Codex用户已经不是开发者，而是做研究、销售、设计的知识工作者，这部分人的增速是开发者的3倍多。
另一边，Claude Code没有跟着拼量，守的是专业工程师首选工具的位置：GitHub上13.8万颗星，压过Codex CLI的不到10万颗。
连定价都贴着打：入门、进阶、顶配三档，两家都是每月20、100、200美元，价格表上已经分不出胜负。
真正的胜负手要得看谁离开发者的日常更近：谁先进终端，谁先到本地。
Linux这一步，抢的正是这个位置。
从2024年macOS桌面版亮相算起，Linux用户等了整整两年。
等来的，已经不是当年那个把网页装进窗口的客户端了，而是一个能读你的项目、开你的浏览器、进你的终端的智能体工作台。
当然，开发者面对的问题也变了。
不再是「哪个平台有ChatGPT」，而是「你愿意让谁住进你的终端」。
