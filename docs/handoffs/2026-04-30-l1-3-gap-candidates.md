# L1.3 vault 补漏 backlog(demand-pull)

## L1.3 重新定义(2026-04-30)

**L1.3 不是 sprint,是持续维护工作流**。"vault 完整度"是 open-ended 问题(国务院/部委/各省一年发数千条政策,vault 不可能全收)。

真正驱动 vault 补漏的是**下游消费拉动**(demand-pull),不是清单驱动(push):

| 信号源 | 触发场景 | 处理路径 |
|---|---|---|
| **评论 thematic_no_link** | P4 评论审阅 LLM 标记"评论引用了 vault 缺的政策" | 进 backlog,按业务直击度 + 引用次数 排优先级 |
| **L3 月报需要展开 X 政策** | 用户做月报时发现 vault 缺关键 cite | 立即单条采集(L1.3 ad-hoc) |
| **主题结晶页缺关键 cite** | 主题页生成时 dangling 引用 | 进 backlog 或立即采 |

**本文档 = 评论侧已识别的 backlog**(W1+W2 已消费 8 条,余 20 条等待 demand 触发)。
